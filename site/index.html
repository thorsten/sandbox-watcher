Everything a sandbox hides, in one place

Sandbox isolates your agents on purpose. Sandbox Watcher gives you the view back, without poking holes in the isolation.

Who is running where

Every sandbox container across all your runtimes, grouped by project, with the agent sessions inside and how long each has been up.

What it is doing right now

The agent's own transcript: recent messages, tool calls and results, with the call in flight highlighted. Plus the processes it runs and the files it changed.

What it reaches

Blocked and allowed destinations straight from sandbox's firewall, proxy and DNS logs. A burst of blocked requests shows up as a notification.

What it costs

CPU and memory sparklines, network and disk I/O, and the container log with follow and filter. Mounts classified as project, persisted, runtime or extra.

The few actions you want

Stop one sandbox or all of them, with a list of the sessions it interrupts. Open the project in your terminal or file manager. Copy names, paths and ready-made commands.

Lives in the menu bar

A tray icon with a per-project summary. Notifications when a session starts, a sandbox stops unexpectedly, or a stale container shows up. Each one switchable.

How it works

No agent inside the container, no daemon, no account. Sandbox Watcher talks to the container runtime you already run.

  1. 1

    Finds your runtime

    Docker, Podman or Apple container, in the same order sandbox looks, honouring DOCKER_HOST, contexts and machines.

  2. 2

    Reads sandbox's conventions

    Containers carry a sandbox.project label and keep session markers and network logs inside. The watcher reads those, nothing else.

  3. 3

    Shows, never leaks

    Environment variable values are never read, only names. Nothing is sent anywhere. Paths to open are derived from the container's own mounts.

Questions

Does it change anything inside my sandboxes?

No. It reads labels, marker files and logs that sandbox already keeps, and it runs read-only commands like ps and git status through the runtime's exec. The only write actions are the ones you click: stopping a container, opening a folder or terminal.

Can it see my secrets?

It never reads environment variable values from containers, only their names. Network logs show hostnames and ports, not payloads. Nothing leaves your machine; the app has no network access of its own.

Which agents does the Activity view understand?

Claude Code, Codex, OpenCode and Pi, each from its own session store inside the container. Any other command still shows its process tree and the project's git changes.

Why are the builds unsigned?

Code signing and notarisation need paid developer certificates. They are planned; until then the first launch needs the usual one-time confirmation, described above.

Is this affiliated with MaibornWolff?

No. Sandbox Watcher is an independent open-source project that builds on the conventions of the sandbox CLI, and notes which release it was tested against.
